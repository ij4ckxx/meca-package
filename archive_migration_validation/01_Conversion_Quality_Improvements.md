# Conversion Quality Improvements — Milestone 1

Fixes confirmed engine defects only, root-caused against real source
XML, real generated output, and the actual running generator code
during the bcj-2025-3130 manual-QA investigation (see
`03_Business_Rule_Recommendations.md` for the full finding-by-finding
classification). No Business Rule was invented; no publisher-supplied
value was cleaned or altered.

## Fixed

### 1. article.xml contrib-group ordering

**Defect**: the reviewer `contrib-group` was emitted after `</abstract>`
instead of alongside author/editor/associate-editor groups, before
`<abstract>` — confirmed against both real hand-curated reference
packages (`Output/MECA_cs-2025-6808.zip`, `Output/MECA_CS-2025-8493_C.zip`).

**Fix**: `generators/article_xml/generator.py` — `_build_article_meta()`
now collects every `contrib-group` from raw.xml up front and emits them
all together at the first `contrib-group` position, instead of copying
each one in raw.xml's own (defective) document order.

### 2. Missing publication metadata (epub/ppub, volume, issue, fpage, lpage)

**Defect**: these 5 fields were correctly extracted, correctly
transformed, and correctly present in `raw.xml` — but `article_xml/
generator.py`'s tag-copy allowlist never included them, despite its own
docstring claiming they were already wired through. Traced end-to-end
through extraction → transform → raw.xml → article.xml to confirm the
loss was isolated to this one allowlist.

**Fix**: extended `_COPIED_VERBATIM_TAGS` in `generators/article_xml/
generator.py` to include `pub-date`, `volume`, `issue`, `fpage`,
`lpage`. Extraction and transformation were not touched.

### 3. submitting-author generation

**Gap**: the source marks the submitting author via
`data-submitting-author="yes"` on a regular `<contrib>`; nothing in the
codebase read that attribute or emitted a `contrib-type="submitting-author"`
element. Not a defect against any existing spec — a genuinely
unspecified case, now implemented as a new capability.

**Fix**: threaded a new `is_submitting_author` boolean end-to-end,
following the exact existing pattern used for `equal_contrib`:
- `extraction/metadata_models.py` — `ContributorRecord.is_submitting_author`
- `extraction/contributor_metadata_extractor.py` — reads
  `data-submitting-author == "yes"`
- `model/article.py` — `Contributor.is_submitting_author`
- `transform/contributor_transformer.py` — copies the field through
- `generators/article_xml/generator.py` — new
  `_build_submitting_author_contrib_group()` emits a
  `<contrib-group><contrib contrib-type="submitting-author">` only when
  at least one author has the flag set; a no-op otherwise. No value is
  fabricated when the source doesn't provide the attribute.

## Deliberately not changed

Per explicit instruction, the following remain source data,
untouched, and are not "cleaned":
- `<degrees>` containing concatenated email/ORCID/counter garbage
  (publisher export defect)
- Associate-editor rows duplicated inside the author `contrib-group`
  (present in source itself)
- `data-type="figshare-statement"` (not renamed to `content-type` —
  no Business Rule authorizes it)
- Corresponding-author affiliation text (source has none to copy)

The reported "unwanted text" (`â€™`) was verified to be a UTF-8 display
artifact, not a file defect — the generated bytes are correctly encoded.

## Confirmed defect, not fixed in this milestone

**Figure/supplement `custom-meta` entries missing** for file-manifest
round label `"R1"`. Root cause: `extraction/round_resolver.py` (ADR-013)
recognizes rounds only via `<article-version>`/vocab-identifier
matching, independent of the file manifest's own round labels — so
"R1"-labeled file entries (16 of 18, including all 12 figures) are
silently excluded before article.xml generation runs at all.

This is a real, reproducible engine defect, but the fix belongs in
extraction/round-resolution, not the article.xml generator, and is
therefore out of this milestone's "generator-only, don't touch
extraction" scope. See `03_Business_Rule_Recommendations.md` for the
full recommendation. Flagged here so it isn't lost.
