# Architecture Compliance Report — Milestone 7 (Package Assembly)

Verifies this milestone's own code against every architecture rule the
task itself restated, using empirical checks (not assumption), matching
the methodology the Milestone 6H Suite Review established.

## 1. "No shortcuts. No architectural redesign."

No existing module's public interface was changed except the strictly
additive `RuntimeConfig.packaging` field (a new optional-in-spirit
section, required only because `RuntimeConfig` is itself a frozen,
fully-specified dataclass — the same pattern every prior generator
milestone used to add its own `*XmlConfig`). No generator's
`generate()`/`_generate()` contract changed. No ICAM field was added,
removed, or renamed. Confirmed via `git`-equivalent diff review of every
touched file (this repository is not yet under version control, so this
was confirmed by direct review of each edit made during this milestone;
see the Implementation Report §1's directory tree for the complete,
exhaustive list of touched files — nothing outside it was modified).

## 2. "No business logic inside Package Builder. Package Builder must only orchestrate."

```
grep -n "BR-0\|BR-1" src/meca_engine/packaging/*.py
→ 0 hits outside comments/docstrings citing already-decided-elsewhere rules
```

`PackageBuilder.build()` contains no conditional branch that encodes a
business rule (no license/DOI/article-type/media-type decision logic).
Its only two "decisions" are: (a) whether a manifest href resolves to a
known `ResolvedFile` (a referential-integrity check, not a business
rule), and (b) whether a DOI is already reserved (delegated entirely to
the injected `DoiRegistry`). Every actual business value (DOI text, file
list, XML content) is read back from bytes the 5 generators already
produced — see `document_reader.py`'s module docstring: "this module's
only job is to read them back out... No value here is derived,
inferred, or defaulted."

## 3. "All XML content must continue coming from existing generators."

```
grep -rn "create_element\|SubElement(\|ET\.Element" src/meca_engine/packaging/
→ 0 hits
```

No file under `packaging/` constructs an XML element. The only XML
operation is *parsing already-generated bytes back* (`document_reader.py`,
via the existing `generators.xml.helpers.parse_document_with_namespaces`
— reused, not reimplemented). Every byte written into the final package
(`_write_xml_documents` in `builder.py`) is `result.document.xml_bytes`,
taken verbatim from a `GenerationResult` the corresponding generator
itself produced and returned — never modified, truncated, or
re-serialized in between.

## 4. "Manifest-driven assembly... never scan directories."

```
grep -rn "\.iterdir\(\)\|glob\(\|rglob\(\|os\.walk\|os\.listdir" src/meca_engine/packaging/builder.py src/meca_engine/packaging/document_reader.py
→ 0 hits
```

`_resolve_packaged_files` derives its copy plan exclusively from
`extract_packaged_file_hrefs(manifest.xml_bytes, ...)` — the generated
manifest's own declared hrefs — cross-referenced against
`context.model.resolved_files` purely to find each href's *source* path
(the manifest itself carries no source path, only the destination href),
never to independently decide "which files exist." The one `rglob` in
the entire `packaging/` package is inside `zip_builder.py`, and it
walks the **already-fully-populated staging directory** (built entirely
from the manifest-driven copy plan) purely to enumerate what to zip —
not to decide package *contents*, which were already fully decided
before `ZipBuilder` is ever invoked.

## 5. "Ensure atomic generation... ALL files exist or NO package exists."

Empirically verified via 4 dedicated tests
(`test_build_leaves_no_artifacts_when_a_generator_fails`,
`test_build_raises_doi_collision_and_cleans_up`,
`test_build_raises_when_manifest_references_unresolvable_href`,
`test_build_cleans_up_a_partially_written_zip_on_zip_failure`), each
asserting **zero** trace of `MECA_*.zip`, `.package-staging-*`, or
`.MECA_*.zip.tmp` survives a failure at every distinct stage of
`build()`. The mechanism: everything is assembled under hidden,
per-article temporary paths; the real filename only comes into existence
via one atomic `os.replace()` (POSIX-atomic on the same filesystem)
after every prior step succeeded; an `except BaseException` block
removes both temporary paths on any failure, including a
`KeyboardInterrupt` or similar, before re-raising.

## 6. "Framework reuse... zero duplicated XML logic."

`packaging/` imports and reuses, rather than reimplements:
`generators.xml.helpers.parse_document_with_namespaces`,
`generators.xml.namespaces.NamespaceManager`, `utils.hashing.compute_stream_checksum_while_copying`,
`exceptions.article_errors.{PackageAssemblyError, DoiCollisionError}`
(both already existed, pre-defined for exactly this milestone — see the
Decision Log), and `generators.result.GenerationResult` /
`generators.context.GeneratorContext` unchanged. No generator was
subclassed, wrapped, or monkey-patched.

## 7. Dependency direction

```
grep -rln "from meca_engine.extraction\|from meca_engine.transform" src/meca_engine/packaging/ src/meca_engine/registry/
→ 0 hits
```

`packaging/` and `registry/` depend only on `generators.*`, `model.*`
(via `GeneratorContext`/`ResolvedFile` type references), `config.*`,
`exceptions.*`, `logging_.*`, and `utils.hashing` — never on
`extraction` or `transform`, preserving the same one-way layering the
Generator Framework itself established and the Suite Review confirmed.
`checkpoint.*` is depended on only by `batch_runner.py`, matching
`10_LLD_01`'s own stated layering (`packaging` sits below
`orchestrator`, and `checkpoint` is a peer utility every layer above it
may use).

## 8. "Do not modify architecture. Do not redesign the ICAM."

`model/article.py` was not modified. `ArticleModel`, `ResolvedFile`,
`RoundInfo`, and every other ICAM type are byte-for-byte unchanged from
Milestone 6H. Confirmed via direct read of the current file against the
Milestone 6H research summary's own quoted field lists — identical.

## Verdict

No architecture violation found in any of the 8 dimensions above. This
milestone's code is additive and orchestration-only, consistent with
every constraint the task instructions stated.
